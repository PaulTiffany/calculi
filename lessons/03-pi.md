# 03 — π-Calculus: Communication That Changes Connectivity

## Need

Distributed systems contain multiple processes that exist concurrently, communicate, gain and lose communication partners, and change network structure while running.

The π-calculus was designed for this world.

## World

The world contains **processes** and **names**.

Names may identify communication channels.

A process may send a name, receive a name, run beside another process, create restricted names, or replicate behavior.

The crucial novelty is **mobility**: communication may change the topology of future communication.

## Primitive intuition

Imagine Alice knows channels \(a\) and \(b\).

Bob knows \(a\), but not \(b\).

Alice sends the name \(b\) to Bob over \(a\).

After that communication, Bob can use \(b\).

So communication has changed the connectivity graph.

That is the key π-calculus move.

## A tiny communication

Notation varies, but schematically:
\[
\overline a\langle b\rangle.P
\]
means “send \(b\) on \(a\), then behave like \(P\).”

And
\[
a(x).Q
\]
means “receive something on \(a\), bind it to \(x\), then behave like \(Q\).”

Placed in parallel:
\[
\overline a\langle b\rangle.P
\;\mid\;
a(x).Q
\]
they can communicate, yielding behavior corresponding schematically to
\[
P\mid Q[b/x].
\]

The important event is not arithmetic. It is **interaction**.

## Names are computational structure

Milner, Parrow, and Walker emphasize that communication links are names and that computation can be represented through communication of names.

A name can therefore be a route, a capability, or a resource for future interaction.

## Behavior and equivalence

For processes, “same output” is often too weak.

We instead ask whether processes exhibit the same observable behavior under interaction.

This leads to notions such as labelled transition systems and bisimulation.

A calculus of interaction requires an account of what an outside observer can distinguish about behavior.

## Historical relation

The π-calculus extends the process-algebra tradition, especially CCS, by making changing connectivity central.

This is an **extension / refinement** relation with explicit historical documentation.

## Boundary

π-calculus does not automatically make process structure itself the native source of names.

Nor does it make perceptual resolution or observer-bounded measurement primitive.

Those are different formal questions.

## Bridge toward reflective process calculi

If a process language can communicate names, a natural next question is:

> Can process structure itself participate in naming, quoting, or reflection?

That leads toward higher-order and reflective process calculi, including ρ-calculus.

## Checkpoint

Suppose process \(A\) knows channel \(c\), and process \(B\) does not. They both know \(a\).

Describe how sending \(c\) over \(a\) changes the system even if neither process's local source code otherwise changes.

Then explain why that phenomenon is awkward to express if your only primitive intuition is ordinary function application.
